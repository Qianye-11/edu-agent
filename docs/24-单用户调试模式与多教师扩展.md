## 2. 数据库结构定义

文件：`<data_dir>/skill_registry.db`（可用 `EDU_SKILL_REGISTRY_DB` 改；SQLite + WAL）

```sql
CREATE TABLE IF NOT EXISTS skills (
  skill_id           TEXT PRIMARY KEY,      -- 必留字段①（= 目录名）
  status             TEXT NOT NULL DEFAULT 'draft',   -- 必留字段② draft|published|…
  create_teacher_id  TEXT NOT NULL DEFAULT '',        -- 必留字段③ 创建者（单用户写占位）
  manifest           TEXT NOT NULL DEFAULT '{}',      -- 必留字段④ SKILL.md front-matter 的 JSON 快照
  file_path          TEXT NOT NULL DEFAULT '',        -- 必留字段⑤ 技能落盘路径（绝对路径）
  title              TEXT NOT NULL DEFAULT '',
  description        TEXT NOT NULL DEFAULT '',
  version            TEXT NOT NULL DEFAULT '0.1.0',
  area               TEXT NOT NULL DEFAULT 'draft',   -- draft|submitted|published|archive
  installed          INTEGER NOT NULL DEFAULT 0,      -- 文件是否真在运行时目录
  verify_state       TEXT NOT NULL DEFAULT '',
  published_at       REAL NOT NULL DEFAULT 0,
  created_at         REAL NOT NULL DEFAULT 0,
  updated_at         REAL NOT NULL DEFAULT 0,
  extra              TEXT NOT NULL DEFAULT '{}'
);
CREATE INDEX IF NOT EXISTS idx_skills_status  ON skills(status);
CREATE INDEX IF NOT EXISTS idx_skills_teacher ON skills(create_teacher_id, status);

-- 教师安装关系：多用户模式用；单用户模式不使用，但表结构先留着
CREATE TABLE IF NOT EXISTS skill_installs (
  teacher_id   TEXT NOT NULL,
  skill_id     TEXT NOT NULL,
  installed_at REAL NOT NULL DEFAULT 0,
  source       TEXT NOT NULL DEFAULT 'self',
  PRIMARY KEY (teacher_id, skill_id)
);
```

**只增不减**：`_ADD_COLUMNS` 会在启动时对老库 `ALTER TABLE ADD COLUMN`（幂等），
**绝不 DROP、绝不删字段**；`ensure_schema()` 返回 `missing_required` 用于自检。

与 `state.json` 的关系：`store.write_state()` 同时写两处 —— `state.json` 继续当生命周期镜像
（现有代码一行不用改），注册表是可查询的"谁创建/什么状态/文件在哪/谁装了"。

实测（迁移已有数据后）：

表: ['skill_installs','skills']   总行数: 5   按状态: {'disabled': 2, 'draft': 1, 'published': 2}

## 3. publish 完整逻辑（确认里面没有 kernel、没有 bind）

`src/edu_agent/skill_market/lifecycle.py`：

```python
def publish(skill_id, actor="E", *, confirm=False, level="patch", session_id=""):
    """审核通过 → 发布。**只做两件事**（铁律 3）：
       ① 把技能完整复制落盘到全局 data/skills/<id>/（store.install_to_runtime）
       ② 更新 status 为 published（state.json + skill_registry.db 同步）

    ## 明确不做的事（红线）
    * 不调用 isolation.bind() —— 会话加载哪些技能是"会话初始化"的事
      （session_bootstrap.ensure_session），发布是全局动作，跟任何会话无关；
    * 不写 skill_installs —— "教师装到我名下"是多用户模式的独立动作；
    * 不碰任何草稿区 —— 草稿依旧住在市场区，Agent 看不到。
    """
    ok, cur, _ = _check_transition(skill_id, "publish")          # 状态机
    if not ok: return _fail(...)
    gated = _gate("publish", skill_id, actor, confirm, cur)       # permissions 闸门
    if gated: return gated

    if cur == "approved":
        man, body, src = store.read_area("submitted", skill_id)   # 源：待审目录
        rep = perm_scan.scan_draft_dir(src, for_publish=True)[2]  # 发布前再扫一次
        if not rep.ok: return _fail(...)
        man = man.bumped(level=level, status="published")
        vdir = store.write_version(man, body, src)                # 版本留档（不可变快照）
        installed = store.install_to_runtime(man, body, vdir)     # ★① 完整复制落盘
        store.archive_area(skill_id, "submitted", reason="published")
    else:                                                         # disabled/rolled_back 重新启用
        latest = store.latest_version(skill_id)
        vdir = Path(latest["dir"])
        man, body = mf.from_document((vdir / "SKILL.md").read_text(...))
        installed = store.install_to_runtime(man, body, vdir)      # ★① 重新落盘

    store.write_state(skill_id, status="published", version=man.version,   # ★② 更新状态
                      actor=actor, area="published", installed=True,
                      dir=str(installed), published_at=time.time())
    _log("skill.publish", ...)                                    # 审计（铁律 5）
    return {"ok": True, "action": "publish", "status": "published",
            "version": man.version, "installed_to": str(installed), ...}
```

**核实**：`lifecycle.py` 全文没有 `isolation`、没有 `bind`、没有 `semantic_kernel`/`Kernel`。
回归测试把它钉死 —— 把 `isolation.bind` 换成会抛 `AssertionError` 的桩，发布仍须成功：

```python
with mock.patch.object(isolation, "bind", side_effect=AssertionError("publish 调了 isolation.bind！")):
    pub = lifecycle.publish("no-bind-skill", "teacher-A", confirm=True)
self.assertTrue(pub["ok"])
```

另外两条也测了：`publish` **不写** `skill_installs`（发布 ≠ 安装）；
`create_teacher_id` **不会被 publish 的操作者覆盖**（创建者只在创建时写一次）。

### 3.1 铁律 2：三重校验做进 submit（不可绕过）

`lifecycle.submit()` 内部依次执行，**不看 `SINGLE_USER_MODE`**：

```python
    rep = perm_scan.scan(man, body, fixture_text=…, skill_dir=d)      # L1 静态权限扫描
    if not rep.ok: return _fail(..., "L1 未过：" + rep.review_note())

    v2 = verifier.verify(skill_id, actor=actor)                        # L2 manifest 权限校验
    if not v2.get("ok"): return _fail(..., "L2 未过：…")               #   （含声明式回放）

    v3 = shadow.shadow_run(skill_id, actor=actor)                      # L3 影子运行 fixture
    if not (v3.get("ok") or v3.get("skipped")): return _fail(..., "L3 未过：…")

    gates = {"L1": rep.verdict, "L2": "pass",
             "L3": "skipped:no-plugin" if v3.get("skipped") else "pass"}
```

* 纯提示词技能没有 `plugin.py` → L3 记 `skipped:no-plugin`（"没有代码可跑"，不是"跳过校验"）；
* L3 有**内容摘要缓存**：同一份插件 + 同一份 fixture 已通过过就不再重跑子进程，
  代码或用例一变摘要就变、缓存自动失效；**失败从不缓存**（必须重跑）。

## 4. 会话初始化加载 skill 的分支代码

`src/edu_agent/skill_market/session_bootstrap.py` —— **`isolation.bind` 只在这里出现**：

```python
def ensure_session(session_id, teacher_id="", *, force=False) -> dict:
    sid = str(session_id or "").strip()
    if not sid: return {"ok": False, "error": "缺少 session_id"}
    single = mode.single_user_mode()          # ← 分支点（唯一使用开关的地方之一）
    mcp_info = {"called": False}

    if single:
        # ① 单用户调试：自动加载**全部 status=published**
        ids, dropped = published_skill_ids()          # 注册表 published → 逐条核对磁盘
        source = "single_user:all_published"
        tid = mode.teacher_id(teacher_id)             # 只用于填字段，业务不依赖
        mcp_info = {"called": False, "reason": "单用户调试模式：不调用 MCP 用户服务"}
    else:
        # ② 多教师正式：问 MCP 用户服务要"该教师已安装"，与 published 取交集
        tid = mode.teacher_id(teacher_id)
        if not tid:
            return {"ok": False, "gate": "teacher_id", ...}
        mcp_info = mcp_user_service.installed_skills(tid); mcp_info["called"] = True
        if not mcp_info.get("ok"):
            # 安全默认：拿不到用户服务 → **拒绝加载**，绝不越权放开全部
            return {"ok": False, "gate": "mcp_user_service", "loaded": [], "mcp": mcp_info, ...}
        ids, dropped = [], []
        for s in sorted(set(mcp_info["skills"])):
            good, why = is_published(s)               # 本人已安装 ∧ published ∧ 文件在
            (ids if good else dropped).append(s if good else {"skill": s, "reason": why})
        source = "multi_user:mcp_installed"

    if not force and isolation.list_for(sid) == ids:
        return {"ok": True, "already": True, "loaded": ids, ...}
    bound = isolation.bind(sid, ids, replace_all=True)      # ← bind 只在这里
    return {"ok": True, "already": False, "source": source,
            "loaded": bound["skills"], "dropped": dropped, "mcp": mcp_info, ...}
```

失败静默 —— 技能加载不了不能拖垮回答。

实测：

        dropped=[{'skill':'graph-node-question-draft','reason':'文件不在运行时目录（data/skills）里'}]

@router.get("/index")
def api_index(q: str = "", teacher_id: str = ""):
    rows = store.market_index(keyword=q)
    single = mode.single_user_mode()                 # ← 分支点
    tid = mode.teacher_id(teacher_id)

def visible_for(teacher_id, *, single_user):

## 8. 一个真实的环境注意点

**MCP stdio 在沙箱里跑不起来**：asyncio 在 Windows 上用**命名管道**做子进程 stdio，
而受限沙箱拒绝 `CreateFile`（`WinError 5`）。现象是 `list_tools` 返回空、`call_tool` 返回 None
（`math` 服务同样如此）。这是**环境限制不是代码问题** —— 正常启动的网关进程里 MCP 工作正常
（实测见上）。排查入口：`mcp_tools.mcp_available()`。
