## 0. 一页看懂（给非技术读者）

**现在为什么难看**（三条，都能对上代码）

1. 预览台是一整块**深蓝底 + 白字**（`.dp-stage` 用 `#0f172a` 铺满），字号只有两档（标题 17px、正文 12.5px）——它看起来像**开发调试页**，不像一张要给全班看的幻灯片；
2. 每一页都是「一个标题 + 一串小圆点」，最多六条并列，没有留白、没有版式变化——这是"土味 PPT"最常见的来源；
3. 预览（浏览器 HTML）和下载出来的 pptx（服务端 python-pptx `pptx_native`）是**两套各写各的坐标**，所以"预览里看到的"和"下载后打开的"从来不一样；中文还可能掉成宋体。

**这次改成什么**（四条）

1. 用一份**数值表（tokens）**统管版面：画布 1280×720、安全边距、字号阶梯、配色占比、线宽圆角。表只有一份。
2. 幻灯片改由**同一个源（SVG）**同时产出预览和 pptx：预览就是这份 SVG 直接显示；导出就是把同一份 SVG 交给本地转换器，变成"能改字的原生 pptx"。
3. 版式从"一页六个圆点"改成 **6 种带槽位的版式**（封面 / 章节 / 要点 / 两栏 / 图文 / 结尾），内容密度超了就提示拆页（**不截断**）。
4. 加一个自动检查（用本机 Edge 无头浏览器）：量**宽高比 / 空白 / 元素碰撞 / 左右失衡**四个指标，先记录今天的数值（基线），再要求"不变差且达标"。

**你会看到的变化**

| | 现在 | 改完 |
|---|---|---|
| 预览台底色 | 满屏深蓝 + 白字 | 白 / 纸白（浅色主题），只有细线和关键词用主色 |
| 字号 | 17px / 12.5px 两档 | 封面 72 / 页标题 44 / 正文 24 / 注释 15（画布 px，四档） |
| 一页内容 | ≤6 条圆点 | ≤5 个模块、每模块 ≤22 字，超出提示拆页 |
| 预览 vs 下载 | 两套渲染，可能不一样 | 同一个 SVG 源，所见即所得 |
| 中文字体 | 可能掉宋体 | 只用本机已装字体（微软雅黑 / Noto Sans SC），并有单测校验 |

**不用你懂的词**：tokens、槽位、SVG、无头浏览器 —— 见 §10 词汇表。

## 2. 路线对比：为什么选 D

三条路线的差别不在"哪个渲染得更好看"，而在**"源"是什么**——源决定预览与导出能不能是同一份东西。

| 维度 | A. HTML + tokens + pptxgenjs 母版 | B. HTML → 原生 pptx（转换流水线） | **D. SVG 单源（选定）** |
|---|---|---|---|
| 预览与导出是否同源 | ❌ 两套渲染，只共享数值 | ✅ 同一份 HTML | ✅ **同一份 SVG** |
| 需要新装什么 | 不用 | `playwright`（**核心依赖**，不是只审计要）[S4]；可驱动已装的 Edge，**不必**下 Chromium；要字体正确还得把字体装进系统目录 [S4] | 不用（`svg_to_pptx.py` 已在 `.deps/ppt-master`） |
| 文字是否原生可编辑 | ✅ | ✅ 矢量优先，装饰走截图兜底 [S4] | ✅ 原生 DrawingML 文本 |
| 版式数值从哪来 | 自写 | 自写 | **直接取上游 style-system** [S1–S3]，上游就是给 SVG 管线写的 [S7] |
| 与本项目已有资产 | 复用现有面板代码 | 全新链路 | 与 `pptx_to_svg.py --roundtrip`（导入旧稿→改）**同源闭环** |
| 与"页签内编辑"计划（docs/19 §8–§12） | 兼容 | ⚠️ 冲突：转换后是"位置"不是"槽位" | ✅ 兼容：编辑槽位 → 重生成 SVG |
| 离线确定性 | ✅ | ⚠️ 依赖浏览器渲染，字体/版本会飘 | ✅ 纯本地脚本 |
| 主要风险 | "预览 ≠ 导出"永远修不掉 | 装依赖 + 字体安装 + 不承诺 1:1 [S4] | 要写"槽位 → SVG"这一小段生成器（§6.1） |
| 结论 | 保留为**回退**与"文档页签"渲染 | 只在"HTML 必须唯一源"时才考虑 | **选定** |

两条**必须纠正的旧说法**（原文有误）：

1. ❌「PptxGenJS 母版能改善我们的导出」——我们的浏览器 deck **只在内存里建模型、从不落盘**（`docpBuildDeck` 注释：*绝不 writeFile*），真正的下载走服务端 `pptx_native`。所以 `defineSlideMaster` [S5] 对**当前导出路径无直接作用**，只在"以后改用 pptxgenjs 出文件"时才相关；
2. ❌「路线 B 只有审计需要渲染器」——`html-to-editable-pptx` 的 `requirements.txt` 把 `playwright>=1.40` 放在 **Core conversion pipeline**，可选审计那块才是 `pdf2image` / `pywin32`；它还带 `scripts/measure.py`(64KB) 与 `tests/test_measure_browser.py` ⇒ **转换本身就要真浏览器** [S4]。

### 3.4 字体（本机实测清单）

已装可用：**微软雅黑** `msyh/msyhbd/msyhl`、**等线** `Deng`、**Noto Sans SC**（OTF + VF）、**Noto Serif SC VF**、**Source Han Serif SC Heavy**、**Arial**、**Georgia**、**Times New Roman**、宋体、黑体。

上游 prefer 但本机**未装**：`Inter`、`Helvetica`、`Yu Gothic`、`Hiragino Sans`、`Microsoft JhengHei`、`Cormorant Garamond`、`Playfair Display`（含上游几套风格指定的衬线标题字体）。

⇒ 规则：**tokens 的 `fonts.stack` 只能写本机已装字体**；`tests/test_ppt_tokens.py` 读系统字体清单校验，写错即测试失败（这是"预览掉宋体"那类 bug 的根治办法，避免再犯）。

### 3.5 一条纪律

数值**只许出现在 tokens JSON**。其它文档（含本文 §3.3、`docs/19`）只能"引用 + 解释"，**不许再抄第二份数字**；要改数值就改 JSON，然后同步这一张表。

## 4. 渲染与坐标：固定画布 + 等比缩放

### 4.1 现在为什么会"比例会漂"

预览台是**固定 CSS px** 塞在**可拖宽**的容器里：`.dp-stage` 的 `padding:16px 18px`、`h4:17px`、`ul:12.5px`，而面板宽度可以是 320 / 680（默认）/ `min(1000px,80vw)`。

折算到 1280×720 画布（`scale = 容器宽 / 1280`，按默认 680 面板、内容宽约 648 计，scale ≈ 1.975）：

- 横向内边距 18px ⇒ **≈35.5 画布 px**（要求 ≥72px）；
- 页标题 17px ⇒ **≈33.6 画布 px**（要求 36–48px）；
- 正文 12.5px ⇒ **≈24.7 画布 px**（要求 18–24px，略超）。

面板一拖宽，同一份 CSS 折算出的画布 px 就变小 ⇒ **同一页在不同面板宽度下与导出的差距不同**，"预览 = 导出"永远不可能成立。这与"数值写在哪"无关，是坐标系问题。

### 4.2 做法

1. 预览台内部固定 **1280×720** 的坐标系（一个 `.dp-canvas`），所有版式元素按画布 px 绝对/网格定位；
2. 外层容器按宽度算 `scale = 容器宽 / 1280`，用 `transform: scale(...)`（`transform-origin: top left`）等比缩放，容器高度随之 = `720 × scale`；
3. `.dp-stage`（改名为 `.dp-canvas` 的底色层）**背景读 `tokens.canvas.bg`**，不再写死 `#0f172a`；
4. CSS 里**不再出现**字号/边距的字面量 —— 由 JS 在读入 tokens 后注入 CSS 变量（`--sl-bg`、`--sl-body`…）；
5. 导出层用同一个常数把画布 px 换成 EMU（§3.3），所以"预览里 72px 的边距"和"pptx 里 54pt 的边距"是同一个东西。

### 4.3 验收

同一页在**面板宽 480 / 680 / 1000** 三种情况下：① 元素两两相对位置（归一化坐标）一致，误差 ≤0.5%；② 与导出 pptx 的文本框位置一致，误差 ≤1 画布 px。截图与几何数据存 `data/tmp/slide_audit/`（临时目录，不入库）。

## 5. 版式与槽位

6 个版式的**槽位定义沿用 `docs/19` §8.4**（不在本文重复），这里只补"上游对应版式"与密度：

| 版式 id | 名字 | 上游对应 pattern [S1–S3] | 备注 |
|---|---|---|---|
| `cover` | 封面 | cover | 主标 + 副标 + 元信息（课题/学情/课时） |
| `section` | 章节过渡 | section divider | 大序号 + 环节名，整页大留白 |
| `bullets` | 要点页 | labeled blocks / steps | **≤5 模块 / 每模块 ≤22 字**；超了提示拆页 |
| `two-col` | 两栏 | comparison | 栏间距按 `canvas.gutter × 2` |
| `media` | 图文 | illustration + caption | 图占一侧，另一侧放注释与要点 |
| `end` | 结尾 | closing / summary | 小结 ≤3 条 + 一句话收束 |

规则：一页只讲一件事；文本一律左对齐、统一基线；页码 `x/N` 画在安全边距**内**；版式只用细线/留白做结构，**不套重卡片**（上游明确"优先开放模块而不是重卡片"）。

## 6. 导出（路线 D 的落法）

### 6.1 调用方式

- 生成器（我们写）：槽位 + tokens → **SVG 文本**（`viewBox="0 0 1280 720"`、真 `<text>`、显式 fill/stroke、禁 filter/阴影/渐变/外链图片）——约束来自上游集成说明 [S7]；
- 转换器（已有）：`python .deps/ppt-master/skills/ppt-master/scripts/svg_to_pptx.py <project_path>`——它读项目的 `svg_output/`，按 canvas contract 校验画布，产出**原生 DrawingML** pptx；
- ⚠️ **不许改 `.deps/ppt-master` 下的任何文件**：它启动时有 `require_skill_integrity()` 完整性校验，改了会拒绝运行。我们只在**外面**调用它；
- 临时工作区放 `data/tmp/ppt_jobs/<job>/`（与 v1.15.0 的 PPT 优化同一条受控落盘规则），产物放 `data/ppt_out/`；**`content/plans/` 一行都不许动**（有测试锁）。

### 6.2 spike 的硬验收（4 条，全过才切主路径）

| # | 验收 | 怎么判 |
|---|---|---|
| 1 | WPS 打开**不提示修复** | 双击打开无"修复"弹窗 |
| 2 | **每个文本框都能改字**（原生文本，不是图片） | python-pptx 遍历：每页 `<p:sp>` 含 `<a:t>`，页数 = SVG 页数 |
| 3 | 字体**不嵌、不替换**：中文落 `微软雅黑`、西文 `Arial` | 读 XML `<a:latin>`/`<a:ea>`；包内无 `fntdata` |
| 4 | 确定性：同一份 SVG 导出两次，页数/文本多集/形状数一致 | 两次导出后比对（文本多集必须 100% 相同，禁止丢字） |

**实测（2026-09-25，本机）：3 页 × 3 套主题全部通过，四条硬验收全过。** 命令：
`.venv\Scripts\python.exe tools\slide_samples.py --to-pptx`

| 验收 | 实测结果（三套主题一致） |
|---|---|
| 转换报告 | `status=passed-with-warnings`，**0 error**（警告是"风格可压缩/未分组"这类建议项） |
| 页数 | pptx 3 页 = SVG 3 页 |
| 原生文本 | 51 个形状，每页文字块 4 / 11 / 15 |
| 不嵌字体 | 包内 `fntdata` **0** 个 |
| 中文字体 | 含中文的 run 19 个，**全部**显式 `ea=Microsoft YaHei`；西文 `latin=Arial`（主题缺省 ea 为空 ⇒ 不显式写就会掉宋体） |
| 内容零丢失 | 逐页逐串比对，0 处缺失 |

结论：**路线 D 的转换环节不需要 Playwright / LibreOffice / 字体安装** —— `--quick-generate` + 一份质量检查报告即可（§6.1）。
仍未做：WPS 真机打开确认"不提示修复"（放到第 3 步与面板联通后一起验）。

### 6.3 回退

若 spike 任一硬验收不过：**导出继续走现有 `pptx_native`**（加 `layout` 参数，默认新渲染，出问题一键切回旧路径），预览仍用 SVG+tokens —— 好处是"观感改造"与"导出后端"解耦，观感改造不会因为导出卡住而停摆。

## 7. 质量闸门（四项指标）

### 7.1 定义（必须按公式算，否则是假精度）

| 指标 | 定义 | 为什么这么定义 |
|---|---|---|
| 宽高比合规 | 版面容器 `w/h` 与 `16/9` 的相对误差 ≤0.5%。**审计对象只有版面容器**（`.dp-canvas`），页列表卡片不参与 | 卡片是列表不是版面，混进来会误报 |
| 安全边距合规 | 内容包围盒四边到画布边缘 ≥ `tokens.canvas.margin` | 直接对应"贴边"这个观感问题 |
| 空白率 | 只统计**文字承载节点**的并集包围盒：`空白率 = 1 − 文字并集面积 / 画布面积`；另**单独记录**"最大空矩形占比"（局部方差图法 [S6]），但**不设卡** | 按"内容包围盒 vs 画布"一刀切会误杀规范自己要的"一侧明显更安静" [S1] |
| 元素碰撞 | 文本节点两两相交面积 > 1px² 才计；**排除**"文字压在底色/图片块上"的有意叠放 | 幻灯片里文字压图是正常设计，不是 bug |
| 视觉失衡 | 以文字并集包围盒的**面积**为质量：`abs(左 − 右) ÷ 总量 ≤ 12%`，上下同理；**版式若在 tokens 里声明了"安静侧"，该侧豁免** | 否则会和"留白"指标互相打架 |

### 7.2 基线（今天）与目标

| 指标 | 基线（按 §4.1 折算 / CSS 事实） | 目标 |
|---|---|---|
| 宽高比合规 | **1.0000 ✅**（`.dp-stage` 已 `aspect-ratio:16/9`） | 保持 100% |
| 安全边距合规 | 横向 ≈35.5、纵向 ≈31.6 画布 px vs 要求 72 ⇒ **❌** | 100% 页合规 |
| 空白率 | 未实测（单块 `h4+ul` 结构，预计 >85%） | ≤45% |
| 元素碰撞 | **0 处**（单列结构） | 0 处 |
| 视觉失衡 | 单列左倾 ⇒ 左右近 100/0（当前版式未声明安静侧） | 版式声明后重算，按版式给阈值 |
| 字号阶梯合规 | ❌（17px / 12.5px 两档，折算 33.6 / 24.7 画布 px，既非页标题也非正文） | 严格取自 tokens |
| 主色占比 | ❌（`.dp-stage` 深蓝满屏 ⇒ ≈100%） | <10% |

> 目标值**不照抄论文的"36%→85%"**：那是论文自己系统的基线 [S6]；我们的基线以上表为准（先量再定，避免"看起来进步了"）。

### 7.3 为什么用 Edge，不用 jsdom

jsdom **没有排版引擎**：`getBoundingClientRect()` 恒为 0，几何指标一个都量不了（现有 `tools/uicheck/panel_check.js` 只能做 DOM/行为检查，保留）。

- 量几何用**本机已装的 Edge**（`C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`）：`tools/slide_audit.mjs` + `puppeteer-core`（npm 包很小，**不下载 Chromium**），或 Playwright 的 `channel:"msedge"`；
- 本机**没有** Chrome / LibreOffice / Office，本方案**不需要**它们；
- 产出：`data/tmp/slide_audit/<页>.json`（几何原始数据）+ 控制台汇总，非零退出即验收失败。

### 7.4 接进哪些测试

| 位置 | 管什么 |
|---|---|
| `tests/test_ppt_tokens.py`（已建，18 例） | tokens 结构合法、字号在区间内、字体本机已装、px↔pt↔EMU 常数、六版式渲染、禁项扫描、不截断换行、密度提示 |
| `tools/slide_audit.mjs`（新，Edge） | 四项指标 + 字号阶梯 + 主色占比；先打印基线，超阈值非零退出 |
| `tools/uicheck/panel_check.js`（扩） | 版式渲染出的 DOM 结构、槽位填充、缩放容器存在（jsdom 够用） |
| `tools/ppt_acceptance.py`（扩） | 端到端：会话 → 幻灯片 → 导出 pptx → WPS 打开 → 内容零丢失 |

## 9. 风险与依赖

| 风险 | 说明 / 对策 |
|---|---|
| 转换器能力边界 | `svg_to_pptx.py` 是别人的"技能包"，我们只做外部调用；**不许改它的文件**（完整性校验）。若某页转换失败，退化为该页截图 + 文字层（与路线 B 同款兜底） |
| 字体在 WPS 里渲染不对 | WPS 不读内嵌裸 TTF [S4] ⇒ 只用本机已装字体（§3.4）+ 单测校验；不引入需要安装的字体 |
| 观感改造动到现有导出 | 导出加 `layout` 参数，默认新渲染，**保留旧路径可一键切回**；`content/plans/` 与 `data/ppt_out/` 的写入规则不变 |
| 指标闸门误杀正常版式 | 定义写在 §7.1（豁免规则），阈值**按版式分别给**；先跑基线再卡验收 |
| 上游风格与本机字体不匹配 | 已核实：上游 prefer 的 6 个字体系列本机未装 ⇒ 用已装替代（微软雅黑 / Noto Sans SC / Arial / Georgia），在 tokens 的 `source` 字段保留出处以便回溯 |
| `dom-to-pptx` 这类"纯前端"库 | 已核实为 npm `dom-to-pptx@2.1.2`、**MIT**，但依赖 `puppeteer^25` + `pptxgenjs^4` + `html2canvas`（包 9.35MB）[S8]，"不用装依赖"不成立；本方案不采用 |

## 10. 词汇表（非技术）

| 词 | 白话 |
|---|---|
| tokens（数值表） | 一张写着"字号多大、边距多宽、用什么颜色"的表；全项目只有一份 |
| 槽位（slot） | 一页里预留的位置，比如"标题放这儿、要点放这儿"；内容按位置填，不靠手摆 |
| SVG | 一种用文字描述图形的格式；浏览器能直接显示，也能被转换成 pptx |
| 原生可编辑 pptx | 下载出来的 pptx 里，文字就是普通文本框，能直接改字（不是一张图片） |
| 无头浏览器 | 没有窗口的浏览器，用来"在后台把网页画出来并量尺寸" |
| 基线 | 改造**之前**测到的数值；以后只要求"不比它差、并达到目标" |
| 母版 / 版式 | 幻灯片里预先定义好的页面样式；改母版会影响所有用它的页 |
