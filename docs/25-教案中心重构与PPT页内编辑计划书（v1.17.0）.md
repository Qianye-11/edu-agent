# 25 · 教案中心重构（文档并入）+ PPT 页内编辑计划书（v1.17.0）

> 老师 2026-09-27 的要求，逐字记下：
> **① 教案中心重构**：(1) 把「教案中心」与「文档」比对清楚两者的所有链路结构；
> (2) 在 (1) 的前提下，把会话侧边面板里的文档内容**都迁移到教案中心**；
> (3) 去掉侧边面板的文档那一系列东西，**恢复到之前的样式**。
> **② PPT 页面改造**：像 WPS 一样的 PPT 显示界面，**把卡片融进 PPT 页内、不要卡片了**，
> 要能像 WPS 那样**在 PPT 页内编辑**。

---

## 0. 一页看懂（给非技术读者）

现在页面上有**两个各管一半的地方**：

| | 教案中心（`教案 × PPT 编排`） | 文档（右侧边面板里的一个圆钮） |
|---|---|---|
| 它管什么 | 排环节（导入/新授/练习…）、看 PPT 小卡片、导出 Word/PPT | 看/改这份教案的正文、看/改幻灯片、下载、导入 .docx、模板填充 |
| 内容存在哪 | **只存在你这台电脑的浏览器里**（换个浏览器/清缓存就没了） | 存在**会话里**（服务端 SQLite）+ 浏览器里一份编辑镜像 |
| 两边怎么连 | 点「预览 PPT」时，**把环节"推"给文档那边**，推完就各走各的 | 收下那份推送，之后改它**不会**回到教案中心 |

所以现在是：**两套数据、两套界面、一个单向的推送**。教案中心页面上写着"改哪边两边一起变"，
其实只在它自己左右两栏之间成立；推到文档那边之后，两边就不同步了。这就是这次要理清的"链路"。

**要变成什么样**：只留一个工作区（教案中心），它同时管"教案正文 / 幻灯片 / 导出"，
数据只有一份（会话里那份）；右侧边面板退回它原来的样子——只做**状态 / 引用 / 知识源 / 会话**四件事。
幻灯片那块从"下面一长串卡片"改成 **WPS 那种样子**：左边一列页缩略图，中间一张大画布，
**点画布上的文字就能直接改**，改完自动存回会话。

**你要拍板的**：见 §9（都给了默认值，不回答就按默认走）。

### 1.3 两者的交叉点（现在真实的样子）

1. **数据不同源**：教案中心 `DZ.steps`（localStorage）vs 文档 `DOCP.slides`（会话 + localStorage 镜像）。
2. **连接是单向推送**：只有 `dzPreviewPPT()` 一条线（教案中心 → 文档），反向没有。
   于是"改哪边两边一起变"（`#view-design` 的副标题）**只在教案中心内部成立**。
3. **导出入口重复、且 payload 不同构**：两边其实**共用同一个函数** `expViaServer()` 与同一个接口
   `POST /api/wps/export`，但送进去的东西不一样——教案中心送 `payload:{title,grade,steps}`（按环节重排），
   文档面板送 `markdown + slides + theme_id + title`（就是预览的那一份，`pptx-deck` 才"预览=导出"）。
   于是同一个老师、同一节课，点两个不同按钮会得到两种排版。合并后只留一条：**送 slides**。
4. **导出位置记忆共用但不可见**：`expViaServer` 统一读 `dzOutDirGet()`（localStorage `DZ_OUT_KEY`），
   而这个值只在教案中心的 `#dzOutDir` 输入框里看得见；面板那侧只有一个「位置」按钮，看不到当前值。
5. **同名函数重复定义**：`dzOutDirGet/Set`、`syncOutDirInput` 各定义了两次（`3345/3348` 与 `3379/3381`），后一份生效——重构时要顺手清掉。
6. **面板被文档"撑大"**：`sp-doc` 把面板从 300px 放宽到 680px，还自动收起圆钮、隐藏副标题；面板的其他 4 个视图并不需要这些。
7. **角色可见性不一致**：教案中心只对教师开放；文档面板对学生也开放（学生答完也能「生成文档」）。合并前必须定这条（§9 第 2 条）。
8. **UI 检查脚本把现状钉死了**：`tools/uicheck/panel_check.js` 里有多条断言写的是"文档在侧边面板里"（第 181/183/188/189/190… 行），重构时必须同步改，否则红。

### 1.4 这段历史（为什么"恢复到之前的样式"是有据可依的）

| 时间 | 发生了什么 | 出处 |
|---|---|---|
| 最初 | `aside#sidePanel`（300px，标题「侧边面板」，内含 **状态 / 引用 / 知识源 / 会话** 四个视图）就是应用自带的右侧面板 | `docs/16` §5.7（回溯描述） |
| 中间 | 文档预览最早是**独立一块 `#docPanel` + 右下角常驻入口**，还一度定在"全局层"，理由是"否则在教案中心导入后看不到结果" | `docs/15` §2、§4 #7 |
| 2026-09-19 第三轮 | 老师反馈两次后并进侧边面板。老师原话：「**我要的是可以进行编辑的预览文档，把查看文档的按钮与预览窗口都给我融进侧边面板，不然两个右边框冗余**」；作者自查：「**我把面板放错了地方**」「之前我把预览做成 `#docPanel` 独立一块，所以右边同时存在两块东西——老师说的"两个右边框冗余"就是这个」 | `docs/16` §5.6、§5.7 |
| 同轮 | 也留了个尾巴：「③ **填入教案中心** | 其实进的是**右侧面板** | **名不副实**：写着"教案中心"，落点却是面板」，处理办法只是**改名**为「按模板填入」 | `docs/16` §5.1 |
| 现在（2026-09-27） | 老师要求把文档整套**搬进教案中心**、面板恢复 4 钮 | 本文 §0 引的原话 |

**结论**：那 4 个视图（状态/引用/知识源/会话）从设计之初就**不依赖文档**，
"之前的样式"是有明确出处的（`docs/16` §5.7 + `docs/14` §2）；而 `#docPanelGrip`（拖宽把手）
与 `#docPanelFile`（文件选择框）本来就**只是文档预览的资产**（`docs/15` §3.2），文档一走就该跟着走。

### 1.6 一句话结论

文档那一整套（正文 / Markdown / 幻灯片 / 结构 + 下载 / 导入 / 模板）**本来就是"教案工作区"该有的东西**，
只是当初挂在了侧边面板上；而教案中心又自带一套简易的环节/卡片。两者合并 = **一个工作区、一份数据、一处导出**。

## 2. 目标 / 非目标 / 红线

**目标**

1. **一个工作区**：教案中心同时管「教案结构 / 文档正文 / 幻灯片」，数据只有一份（会话里那份）。
2. **侧边面板恢复原样**：只剩 状态 / 引用 / 知识源 / 会话 四个圆钮，去掉文档相关的一切外壳。
3. **幻灯片像 WPS**：左侧页缩略图 + 中间画布，**页内直接改字**；**不再有卡片列表**。
4. 导出入口收成一处；"教案 → PPT"仍然"改哪边两边一起变"（这次是真的双向）。

**非目标（本轮明确不做，避免跑偏）**

- 不做自由拖拽文本框、不开放任意字体/字号/颜色（会破坏 `docs/22` D4/D8 的 tokens 契约与审计闸门）。
- 不做插入图片/形状/图表、不做动画与切换效果、不做备注页与母版编辑。
- 不做多人协同、不做版本历史/评论。
- 不改导出内核（`svg_to_pptx` 那条链路本轮一个字节都不动，见 §6.3 的风险规避）。

**红线（沿用，全部要自动化检查）**

- `content/plans/` 一个字不写；模板原稿只读（填充在副本上做）。
- 预览链路**不落盘**（只有导出与填充产物落 `data/ppt_out/`，中间件进 `data/tmp/ppt_jobs/`）。
- 只写 `content/ppt_templates/`（模板导入时）；导出/填充不许写入会话库以外的位置。
- 不推远端、不合并分支（老师说推才推）。

## 3. 决策（D1–D8，都有理由；不同意第几条就单独说）

| # | 决策 | 为什么 |
|---|---|---|
| **D1** | **数据真源 = 会话里的那份**（`session_docs`：`slides + markdown + title`）。`DZ`（localStorage 那套 steps）**退役**，只做一次性迁移。 | 会话那份已经在服务端、导出与填充都在用；本地那份换个浏览器就没了，不能当真源。`clean_slides` 已经把字段合同定死（`layout/name/title/minutes/label/blocks/caption/closing/subtitle/meta/left/right`），迁移有明确目标。 |
| **D2** | **教案中心 = 三段式工作台**：顶栏（课题/导出/主题模板）+ 左栏（环节或页缩略图）+ 中栏（舞台：文档 / 幻灯片）+ 右栏（提示与属性，可折叠）。 | 左栏在"文档模式"是环节列表、在"幻灯片模式"是 WPS 式页缩略图——同一个位置两种含义，符合两种工作的直觉；中栏是唯一"看东西"的地方，避免现在"左边编排右边卡片、面板里又是另一套"。 |

## 5. 第二部分：PPT 页内编辑（WPS 式）（R10–R12）

### 5.1 交互规格（老师视角）

| 动作 | 结果 |
|---|---|
| 看 | 中间一张 16:9 大画布（等比缩放，白底+阴影）；左边一列页缩略图；上面模式页签与工具栏 |
| 改字 | **点一下画布上的文字** → 该文字变成输入态（原文字隐藏、同位置出现编辑框，字号位置与原来一致）→ 直接打字 |
| 换行 | `Enter` 在块内换行（不新增页）；`Esc` 或点空白退出编辑 |
| 选中整块 | 双击进入"整块替换"（全选该块文字），单击进入"插入点" |
| 撤销 | `Ctrl+Z` / `Ctrl+Y`，本地 20 步（够用，不入库） |
| 换页 | 左栏点缩略图 / 页码条 上一页下一页 / `PageUp`·`PageDown` |
| 页操作 | 缩略图悬停出现：复制页 / 删页 / 上移下移；底部「+ 加一页」 |
| 换版式 | 右栏下拉（6 个版式，带小图示意）；换版式不丢文字 |
| 提示 | 右栏显示本页字数（超 22 字标黄）、服务端警告（建议拆页）、"已保存/已改过" |
| 保存 | 停打 700ms 自动存回会话（沿用现有 `/api/slide/save`），状态行显示"已保存" |
| 模板页 | 填充预览时：点某个框 → 右栏显示"这是模板第 N 页的『标题』槽"，**v1 只读**（改字请切回我们的版式或改教案正文再重填） |

**明确不做**：拖拽文本框、任意字号字体颜色、插入图片/形状、动画与切换、备注页。

### 5.2 技术方案（三步，都可单测）

**第一步：服务端给"可编辑盒子"（R10）**

- `ppt_svg`：`text()` / `paragraph()` 增加一个可选 `slot` 标签；`Canvas` 上挂一个收集器，
  渲染时顺手记下每个槽的**可编辑区域**（设计像素 1280×720）：`{slot, x, y, w, h, size, align}`。
  - 段落槽：`w = max_w`，`h = 行数 × 行距`（点击区域就是这一整块）；
  - 单行槽：`w = 该行实测宽（或版心宽）`，`h = 字号 × 行距`；
  - 同时给 `<text>` 加 `data-slot="…"`，方便前端"编辑时隐藏这一槽"。
- `slide_deck.build_deck(..., annotate=False)`：为真时把 `boxes` 一并返回（`{pages, boxes, layouts, warnings, stats}`，**新增键，向后兼容**）。
- `POST /api/slide/render` 传 `annotate=True`；**导出路径保持 `annotate=False`**（D8）。
- 槽位标签（与 `clean_slides` 字段一一对应，不新造概念）：

| 版式 | 可编辑槽 |
|---|---|
| `cover` | `title`(封面标题)、`subtitle`、`meta` |
| `section` | `label`(小节标签)、`title` |
| `bullets` | `title`、`block[0..n].label`、`block[0..n].text` |
| `two-col` | `title`、`left.heading`、`left.bullets[i]`、`right.heading`、`right.bullets[i]` |
| `media` | `title`、`caption` |
| `end` | `title`、`closing` |

**第二步：前端页内编辑层（R11）**

- 叠加层放在**同一个被 `transform: scale()` 的容器里**（`#dpCanvas`），用设计像素绝对定位
  → 与 SVG 天然对齐，**不需要**任何像素测量（这点很关键：jsdom 量不到宽度，而现有面板检查正因此吃过亏）。
- 进入编辑：给 `#dpCanvas [data-slot="X"]` 加 `visibility:hidden`，同位置插入 `contenteditable` 覆盖框
  （字号 = 盒子 `size`、字体 = 主题字体、行高与 SVG 的 `lh` 一致）→ 退出编辑反过来。
- 写回：`slot → 字段`的映射函数（纯函数，可单测）：`block:2:text` → `slides[i].blocks[2].text`；`left.bullets:1` → `slides[i].left.bullets[1]`；`title` → `name`（封面/结尾页 → `title`）。
- 保存：沿用 `docpSaveSlides()`（700ms 防抖 + 服务端 `clean_slides` 清洗 + 重取 SVG）。
- 缩略图：直接用 `DOCP_SL.pages`（每页 SVG）缩放进左栏；拖动排序用 pointer events（不引库）。
- 撤销栈：每次提交前 `JSON.stringify(slides)` 入栈（20 步），`Ctrl+Z/Y` 恢复后走同一条保存链路。

**第三步：收口（R12）**

- 删掉卡片列表与表单编辑器（`docpCardHtml` / `docpEditorHtml` / `.dp-slide` / `.dp-cardbar` / `.dp-edit` 样式），
  把"改标题/时长/标签/版式"放进右栏属性区（页内编辑覆盖不到的部分）。
- 填充预览页的"点槽高亮"（数据来自 `fill.plan` 的 `fills[].geo + shape_index`）。
- 全量验收（§7）+ 文档与 CHANGELOG。

### 5.3 为什么这么选（备选方案与弃用理由）

| 方案 | 结论 | 理由 |
|---|---|---|
| **SVG + 叠加层**（本方案） | ✅ 选它 | 预览与导出共用同一份 SVG（`docs/22 D13` 已锁）；盒子几何在发射时就有，零测量；缩放天然对齐 |
| 前端自己拼 HTML 编辑（像旧版 `dz-slides`） | ❌ | 预览与导出重新变成两套渲染，历史踩过（"预览=导出"永远修不掉） |
| 引入第三方在线 PPT 编辑器（如 OnlyOffice/pptxjs 的编辑模式） | ❌ | 与"本地部署 + 不联网 + 模板原稿只读"冲突；授权与体积都不可控 |
| 把 pptx 交给 WPS 编辑（`/api/wps/export` 后人工改） | ❌ 作为主路径 | 老师要的是"在页面里改"，不是"导出后再改"；WPS 那条链路保留作最终精修 |

### 5.4 风险与规避

| 风险 | 规避 |
|---|---|
| 叠加层与 SVG 的换行位置算得不完全一样 → 编辑时看到的重排 | 编辑时**隐藏原槽文字**、只用叠加框（所见即所编）；退出后由服务端重排一次，行数变化属于正常重排（右侧立刻显示新字数） |
| 编辑中重渲染打断输入/跳滚动 | D7：编辑中不整页重画；失焦后再取 SVG（沿用 `docpPaintPage` 的"只换舞台不重建 DOM"经验） |
| `data-slot` 影响导出转换器 | D8：只在预览开；并用 `tools/ppt_acceptance.py --with-wps` 复验导出（28 项）。**审计侧已核实无风险**：`slide_audit` 是逐元素读属性（`slide_audit.py:106-120`），多一个属性不影响判定；真正需要防的是第三方 `svg_to_pptx`（历史上出过"多出来的东西被质量检查拒绝 → 静默回退旧版式"） |
| 编辑后字号越阶/溢出，审计闸门红 | 编辑只改文字不改字号；`slide_audit --gate` 进验收矩阵（0 error） |
| 老师习惯"卡片列表能一眼看全" | 缩略图栏承担这个职责（WPS 也是这样）；并保留"结构"页签看全文字 |
| 合并期间两处 UI 同时存在（半成品） | 分两轮：R8 先"搬过去并双跑对拍"，R9 再"删面板那套"；每轮结束都是可用状态 |

## 9. 需要你拍板（都有默认值，不答就按默认）

1. **中栏内容**：默认「页签切换：文档 / 幻灯片」（一次看一个）。若要**同屏**（文档在上、PPT 在下，或左右分屏），请说——同屏会让舞台变窄约 40%。
2. **学生角色**：教案中心只有教师能进。默认把学生那条「生成文档」改成**直接下载 Word**（学生不需要改幻灯片）。
3. **模板填充页**：默认 v1 **只读**（点一下告诉你"这是模板的哪个槽"）。要 v1 就能在填充页上直接改字，请说（多一轮，走 `mapping` 接口）。
4. **旧编排数据**：默认把浏览器里那份 `edu_design_v1`（你现在编排的环节）**一次性转进会话**并留备份。不想转就说，我直接清掉。
5. **Markdown 页签**：默认保留，但收进右栏"源码"（折叠），不再占一个主页签。
