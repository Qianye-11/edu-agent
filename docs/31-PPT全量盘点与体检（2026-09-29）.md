| 红线 | 实测 | 结论 |

| `.deps` 只读、不入库 | 只读取编译；`git ls-files .deps` = 0 | ✅ |
| AGPL 不进仓库/链路 | 仓库里 0 个 guizang 文件；注册表只记"来源"不抄代码 | ✅ |
| **`content/plans/` 一个字不写** | ⚠️ **口径要修正**（见下） | ⚠️ |

**⚠️ `content/plans/` 的实测与口径修正**：那里现在有 **13 HTML + 5 pptx + 3 docx**。查代码后确认：

* **新版式导出 / 模板填充 / 配图 / 中间件** 都不写它（默认 `data/ppt_out/`）—— 这一半的红线成立；
* 但 **老的 Word / 旧版式 PPT 导出**（`wsl_docx.export_best` → `wps_export.resolve_out_dir`）在没选目录时
  **默认就落 `content/plans/`**（`wps_export.OUT_DIR = ROOT / "content" / "plans"`），
  而且界面上的「导出位置…」也写着"留空则存到项目内 `content/plans`"，`/files` 静态路口也挂在它上面。

⇒ 所以准确的红线是：**"中间件、模板库、配图、新渲染导出不许写 `content/plans`；老的 Word/旧版式导出按它自己的默认落这里"**。
`docs/22`/`docs/23` 里"一个字不写"那句要按上面这句改，否则后人会以为这里有 bug。

## 9. 环境事实（本次盘点的副产物）

本机 Web 服务（`127.0.0.1:5174`）会被这个会话**反复回收**——盘点期间它自己死了两次
（`Get-Process python` 直接为空）。所以：

* 闸门第 [3]、[4] 摊**依赖服务在场**：现在服务没起会标 **⏭️ 跳过**（不再假红），
  退出码 **2**、矩阵里单列，**不算全过**（见 §7 第 1 条）。
  实测两条路径：服务没起 → `7/7 全过，但有 2 摊被跳过`；服务起来 → **9/9 全过**。
* 那两摊单独跑也是绿的：`--only=smoke,panel` → **2/2**（PPT 体检 49/49 · 面板 305-0）。
* 想一次拿完整 9/9：**用"起服务 + 跑闸门"同一条命令**（先 `Start-Process` 起
  `src\edu_agent\web_server.py`，`HTTP 200` 之后再跑闸门）。
