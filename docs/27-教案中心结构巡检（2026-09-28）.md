# 教案中心结构巡检（2026-09-28）

> 起因：老师要「检查教案中心的结构」。这一份是**实测巡检**，不是读源码猜的：
> 用 `tools/layout_probe.py`（新做的量尺）在真浏览器里量每个区块的高度，配截图人眼复核。
> 结论一句话：**结构骨架没问题（页签 + 左栏 + 舞台 + 状态栏），但「幻灯片」页签里
> 八条"操作条/卡片"把画布挤到只剩三分之一** —— 编辑时看的是 40% 缩放的幻灯片。

## 一、教案中心的骨架（四段，自上而下）

```
教案中心
├─ 标题区        教案工作台 + 一句副标题（"课题、正文、幻灯片是同一份内容…"）
├─ 工具栏 (#dzEditBar)   课题 · 学情/课时 · [生成骨架] [＋添加环节] ··· 已自动保存 · [立即保存] · [下载▾]
│                        （结果条 wzResultBar 平时不占位；#dzOutDir 是隐藏的状态载体）
├─ 页签 (#wzTabs)        教案 | 文档 | Markdown | 幻灯片
├─ 内容区 (#wzGrid)
│    ├─ 左栏 (#wzLeft)    教案=环节目录 / 幻灯片=页缩略图 / 文档·Markdown=收起
│    └─ 舞台 (.wz-stage)  教案=环节卡片(#wzPlanPane) / 其余=文档外壳(#wzDocPane)
└─ 状态栏 (#wzStatusBar)  页码 · 篇幅 · 缩放 · 主题 · 提示 · 保存状态
```

页签规则（已核实，正常）：`doc`/`md` **收起左栏**并把宽度让给正文；`教案`/`幻灯片` 用左栏；
「生成骨架 / ＋添加环节」只在**教案**页签显示（R12.5 的收口生效）；下载只有**一处**入口（无历史重复）。

| 高 | 块 | 说明 |
|---:|---|---|
| 28 px | `.dp-slhead` | 主题 / 模板 / 模板+ / 删 / 填充 / 对齐 / 统计 |
| 29 px | `.dp-tooltabs` | 开始 \| 插入 \| 设计 \| 放映 |
| 56 px | `.dp-toolgroup` | 当前组的按钮（开始组：B I U 左中右 A- A+ 查找 替换 ⌨） |
| **301 px** | `.dp-stageflex` | **画布在这条里** |
| 42 px | `.dp-pagebar.dp-objs` | 选中：xxx · 吸附 · 上移/下移一层 · 回原位 · 删除 |
| 24 px | `#dpPgBar` | 上一页/下一页 · 第 n/N 页 · 适应窗口 · 缩放 · 网格 · 浏览 |
| **206 px** | `.dp-pagebar.dp-props` | **「本页属性」卡片**：版式下拉 / 时长 / ＋加一块 / 提示 |
| 62 px | `.dp-note-bar` | 备注（这一页要讲什么）+ 0/2000 |

**人眼复核**：截图 `data/tmp/wzshots/wz_slides-sel-obj-tall.png` —— 画布确实只有中间一条，
上下各堆着好几条；右栏"属性"面板还占着横向空间。

## 三、发现（按影响排序）

### P0-1 「本页属性」一张卡吃掉 206px（占条张的 44%）
- 内容：版式下拉 + 时长 + ＋加一块 + "每块建议 ≤22 字"提示。
- 问题：它是**页面属性**，却被放在舞台下方、翻页条之后；而且**一行能装下的东西占了 206px**。
- 影响：画布被压到 40% 缩放，老师编辑时看不清自己写的字。
- 建议：压成**一行紧凑条**（版式 + 时长 + 加一块，≈34px），或并进右栏"页面"段。
  预期：画布 +170px → 可见高 ~460px（≈64%），基本"能看清"了。

### P0-2 三条同款"操作条"并排，职责靠猜
- `.dp-objs`（对象）、`#dpPgBar`（翻页/缩放）、底部条（加页/撤销/重做）**样式完全一样**。
- 而且**没选中任何东西时对象条照样占 42px**（按钮只是灰着）。
- 建议：① 对象条**只在选中时出现**；② 「＋加一页 / 撤销 / 重做」并进翻页条（或贴到左栏缩略图头）。
  预期：常态省 **66px**。

### P1-1 重复入口
| 功能 | 入口一 | 入口二 |
|---|---|---|
| 网格 / 适应窗口 / 缩放 | 设计组（`dpGrid2/dpZoomFit2/dpZoomIn/dpZoomOut`） | 翻页条（`dpGrid/dpZoomFit/dpZoom`） |
| 层级 / 删除 | 对象条（上移/下移/删除） | 右栏"属性 · 对象"（层级 / 删除这个对象） |
| 页码 / 缩放 / 主题 | 翻页条 | 底部状态栏 |

建议：同功能留"贴着操作对象"的那一处，另一处改只读显示或去掉；状态栏只留**保存状态 + 当前提示**。
（注意：对象条与右栏的"层级/删除"名字一样但语义不同 —— 前者是**版式槽位**的层级，
后者是**自由层对象**之间的叠放；这层歧义要改文案，例如"对象层级（在形状/图片之间）"。）

### P1-2 窄屏（≤~1180px）工具栏换行，「下载」独自跑到第二行
- 实测：教案页签在 1150 宽时 `toolbar h=96 · rows=4 · downloadWrapped=true`（截图复核一致）。
- 问题：下载是**主操作**，换行后与"立即保存"脱开、位置漂移。
- 建议：工具栏不换行 + 「下载」`margin-left:auto` 钉在右侧；窄屏把"已自动保存"收成短文案或图标。

### P2-1 教案页签的标题/统计有两处来源
静态 HTML 里是「教案结构 + #dzStat」，`dzRender()` 又把它改成「这一环节 / 全部环节」。
行为正确，但同一处文案两处定义，后人容易只改一边。建议静态里留占位 + 注释指向 `dzRender`。

### P2-2 左栏随页签换语义，但外形一模一样
教案=「环节 (5)」、幻灯片=「幻灯片 · 共 N 页」、文档/Markdown=隐藏。有标题区分，
但样式、位置、交互（点一下切换）都一样。建议标题前加图标或换色，让"我现在在看哪种列表"一眼可辨。

### P2-3 隐藏的历史载体
`#dzOutDir`（`display:none`）只是导出位置的存放处。无害，但建议要么删掉、要么在源码里写清它是状态载体。

## 五、建议的落地顺序（都不大，一天内能做完）

1. **P0-1 + P0-2**：把「本页属性」压成一行、对象条按需出现、加页/撤销/重做并进翻页条
   → 画布从 33% 提到 ~60%，**这是老师体感最明显的一条**；
2. **P1-2**：窄屏工具栏不换行、下载钉右侧；
3. **P1-1**：去重（设计组 vs 翻页条、对象条 vs 右栏、状态栏 vs 翻页条）；
4. **P2-1~3**：文案与占位的收口。

> 巡检工具留在仓库里：`tools/layout_probe.py`（`--tab=slides|plan --size=W,H`），
> 以后改版式、加面板前先量一把，别再让"画布被挤到三分之一"这种问题靠肉眼发现。

## 六、整改复测（R25 结构 / R26 文案与按钮，2026-09-28 当天完成）

本巡检里的 P0/P1 已经落地两轮，复测数字（同一工具、同一视口 1570×1305）：

| | 巡检时 | R25 后 | R26 后 |
|---|---|---|---|
| 内容区里的块数 | 9 | 7 | **6** |
| 非画布部分 | 471 px（54%） | 259 px（35%） | **231 px（32%）** |
| 舞台可见高 | 289 px | 404 px | **404 px** |
| 画布缩放 | 40% | 80% | **80%** |
| 画布占内容区 | 33% | 54% | **57%** |

* **R25**：下载菜单挂到 body（几何裁剪，非 z-index）；去掉对象条 / 本页属性卡 / 底部条；
  属性条搬到工具按钮下面；翻页条只留 翻页·页数·适应窗口·加一页。
* **R26**：内部术语从前端撤掉（ppt-master / content/plans / data/uploads / 同事的 agent …）；
  槽位名说人话（「要点 1」而不是 `block:0`，原始名留在 `data-slot`）；
  主题·模板控件搬进「设计」组、页头那行取消；「导入」与"下载在顶栏"只在改正文的页签显示；
  状态栏不再重复页码/缩放/主题。
* 两轮都踩到并修掉的坑：**`docpRenderSlides` 拿 `#dpTpl/#dpTheme` 当"外壳在不在"的判据** ——
  控件一搬走，判据永远为假 → 自己调自己 → 栈溢出（jsdom 直接 `RangeError`）。
  现在改用每组成员都在的 `#dpPropsRow` 做锚点。

详细清单见 `docs/28` §五。
