# 后端知识库颗粒度与检索优化（2026-09-27）

## 1. 本轮结果

- 教材由 151 个粗块升级为 **296 个细粒度语义块**。
- 切块目标约 700 字，块间保留约 90 字语义重叠。
- 52 个原始章节全部保留 `parent_id / chunk_index / chunk_count` 父子坐标。
- 每块新增 `content_hash / is_sidebar / has_figure / fig_nums / fidelity / content_role` 元数据。
- 15 题黄金集：Dense Recall@3 由 14/15 提升为 **15/15**；Hybrid Recall@3 为
  **15/15，MRR 0.967**。
- `edu_wiki` 仍为 24 块，教材重建不会再误删 Wiki collection。

## 2. 主要改造

### 2.1 统一语义切块

`src/edu_agent/chunking.py` 是教材与上传 PDF 共用的切块入口：

1. 优先在换行、句号、问号、感叹号和分号处断开；
2. 单句超过上限时才做硬切；
3. 相邻块保留少量重叠，降低定义、条件、推导跨边界丢失的概率；
4. 上传 PDF 按页切分，`page_start/page_end` 不跨页，引用页码更可信。

### 2.2 真正的混合召回

旧实现虽然计算了 BM25，但只保留同时出现在 Dense 候选池中的文档，且后续按 Dense
距离重新排序，RRF 结果基本失效。新实现采用：

```text
Dense Top-N ─┐
             ├─ 候选并集 → RRF + 轻量结构先验 → 可选 rerank → Top-K
BM25 Top-N  ─┘
```

主节优先由硬排序改为软加权；用户明确询问“小结、复习题、阅读与思考”等内容时取消
主节偏置。

第二阶段继续把章节、节号、标题加入 BM25 文本域，并在融合分数中加入可解释的标题匹配
弱先验。同一 `parent_id` 默认最多占 Top-K 中两个位置，避免一个长章节的相邻重叠块挤掉
其他有效证据。

### 2.3 教学角色颗粒度

保留来源层的 `kind=section`，另行推断每个语义块的 `content_role`：

| 角色 | 当前块数 | 作用 |
|---|---:|---|
| `concept` | 56 | 定义、概念类问题的弱先验 |
| `example` | 107 | 例题、求解类问题的弱先验 |
| `exercise` | 22 | 练习、习题类问题的弱先验 |
| `explanation` | 88 | 普通教材讲解 |
| `sidebar` | 23 | 阅读、探究等旁栏内容 |

角色只提供小幅加权，不覆盖 Dense/BM25 的主体相关度。实测曾发现过强的“定义”加权会把
第五章小结排到 5.2 节之前，因此最终将其收敛为弱先验，并以黄金集 MRR 不回退为准。

### 2.4 自动恢复被 PDF 文字层损坏的小节号

教材中的艺术字小节号会被抽成 `422!`、`511!`。插页结束后，原来的目录粗切无法识别
主节已经恢复，导致指数函数正文被标成“阅读与思考”。入库时会将这类标记与已经存在的
章节表核对，确认后为后续细块恢复 `4.2`、`5.1` 等坐标，不凭空创建章节。

### 2.5 安全重建与回滚

入库不再删除整个 `chroma_db`：

1. 创建临时教材 collection；
2. 完成 embedding 并校验数量；
3. 将旧 `edu_textbook` 重命名为带时间戳的 backup；
4. 将临时 collection 切换为 `edu_textbook`；
5. 保留最近一个回滚版本；
6. 不影响同目录中的 `edu_wiki`。

当前可用 collection：

| Collection | 数量 | 用途 |
|---|---:|---|
| `edu_textbook` | 296 | 当前教材索引 |
| `edu_wiki` | 24 | 已学习概念 Wiki |
| `edu_textbook_backup_20260927_210439` | 151 | 本轮优化前的回滚版本 |

切换 collection 后应重启 Web 服务，使旧的 Chroma/BM25 进程缓存完全释放。

### 2.6 PDF 与 Wiki 修复

- 上传 PDF 每块写入独立 `chunk_id`，旧数据缺 ID 时检索器也会生成稳定回退 ID，避免
  多块全部坍缩为同一个结果。
- 相同 PDF 重复上传直接复用已有记录，不再生成孤儿原件。
- PDF 元数据 JSON 使用临时文件原子替换。
- Wiki 内容变化使用 `upsert` 更新，不再对已有 ID 调用 `add`。
- Wiki 只在教材知识范围下作为证据；选择某份 PDF 时不会混入教材 Wiki。

### 2.7 索引 manifest 与健康检查

`chroma_db/edu_textbook_manifest.json` 记录建库时间、块数、embedding 提供方/模型/维度、
切块参数及所有结构化源文件的 SHA-256。`GET /api/knowledge-health` 会对 collection、
manifest、源文件和用户 PDF 目录执行只读一致性检查；当前结果为 `healthy`，无 issue。

## 4. 后续建议

当前颗粒度已经从“整节级”提升到“语义段级”，下一步不宜继续机械缩短，而应建设真正的
`concept / example / exercise` 教学卡，并把黄金集扩充到不少于 100 题，分别覆盖概念、
例题、习题、旁栏、范围外问题和上传 PDF。公式图片仍应坚持“页码 + 原页图”策略，未经
人工或视觉模型核验，不把缺失公式补写进纯文本知识库。
